# SmartOrchard Mobile — Kotlin / Jetpack Compose

Нативный Android-шаблон по согласованному мобильному макету «Доска сада»: Kotlin, Jetpack Compose и Material 3. Все экраны написаны на Compose; HTML и WebView не используются. Приложение запускается с моковыми данными и сохраняет изменения на устройстве.

## Запуск в Android Studio

1. Откройте Android Studio → **Open** → выберите папку `smartorchard-mobile-kotlin`, рядом с React-проектом дэшборда.
2. Дождитесь **Gradle Sync**. При первом открытии нужен интернет для зависимостей. При запросе установите **Android SDK Platform 37** и инструменты сборки через SDK Manager.
3. В **Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK** выберите исправный JDK 17 или совместимый JDK из Android Studio. На этом компьютере проверен `C:\Program Files\Eclipse Adoptium\jdk-17.0.17.10-hotspot`. Если Studio сообщает об отсутствующем `jbr/lib/jvm.cfg`, выберите этот JDK.
4. В Device Manager создайте эмулятор Android 8.0 / API 26 или новее, либо подключите Android-телефон с включенной отладкой по USB.
5. Выберите конфигурацию **app**, устройство и нажмите **Run ▶**.

`npm` и Node.js для этого проекта не нужны. Gradle Wrapper включён в папку. Локальный `local.properties` указывает на установленный SDK; при переносе на другой компьютер Android Studio создаст собственный файл.

## Сборка из терминала

Откройте терминал в папке проекта. Для стандартного окружения с установленным JDK:

```powershell
.\gradlew.bat assembleDebug
```

Для текущего Windows-окружения предусмотрен запуск Gradle без фонового процесса:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Eclipse Adoptium\jdk-17.0.17.10-hotspot'
.\build-debug.bat
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. Это демонстрационная debug-сборка для установки на тестовое устройство. Для публикации потребуется release-подпись.

## Что работает

- **Доска сада:** выбор сада, состояния деревьев, фильтры, страницы рядов и мест, паспорт выбранного дерева. Действующий демополив отмечается отдельно синей полосой.
- **Создание сада:** выбор или создание культуры, площадь, дата, схема посадки; расчет `N = floor(Sга × 10000 / (Lряда × Lдерева))`. Задается число мест в полном ряду, последний ряд может быть неполным. Пустые клетки не создают деревья или QR. Ограничение шаблона: 10 000 деревьев, до 100 рядов и до 100 мест в ряду.
- **Культуры:** название, сорт, расстояния между рядами и деревьями; проверка дубликатов. Из формы сада можно создать культуру и вернуться к заполненному черновику.
- **Осмотры:** фото из файлов или камеры, пример фото, заметка, состояние. По умолчанию используется прошлое состояние дерева. ИИ-сценарий возвращает демонстрационные диагноз и рекомендации, позволяет их исправить и явно сохранить для дерева. Исходный ответ ИИ сохраняется отдельно от пользовательских правок. Сохранение осмотра и состояния выполняется одной локальной операцией. Фото — JPEG/PNG до 10 МБ.
- **QR:** настоящий QR с постоянным UUID дерева, сканирование камерой, поиск по ряду и месту, открытие по тексту QR. В карточке дерева есть печать этикетки. Формат: `smartorchard://tree/<uuid>`. Сканер распознаёт этот формат; старые URL из HTML-макета не поддерживаются.
- **Печать:** системный диалог Android с настоящими QR на листе A4, от 1 до 12 этикеток; можно выбрать «Сохранить как PDF». Bluetooth-поиск и подключение виртуальных принтеров демонстрируют интерфейс без физической печати.
- **Полив:** создание и просмотр зон из произвольных клеток, редактирование, запрет включения дерева в две зоны. Интервалы времени не пересекаются в одной зоне; конец интервала не включается. Это автоматический сценарий по времени, без задач для сотрудников.
- **Затраты:** записи непосредственно для сада, категории, количество, цена, итог с точным денежным округлением, сценарная окупаемость. При неположительном годовом результате срок не рассчитывается.
- **Ещё:** сады, культуры, демопринтер, сведения о локальных данных, переключатель демонстрации отсутствия сети для ИИ.

## Моковые данные и ограничения

Исходный набор находится в `app/src/main/java/com/smartorchard/mobile/data/SeedData.kt`: два сада, 172 дерева, культуры, зоны, расписания и затраты. Существующие сады сохраняют условный реестр мобильного макета (100 и 72 дерева); для **новых** садов количество вычисляется по площади и схеме посадки.

Дата демонстрационных сценариев — **29 октября 2026**, время предпросмотра полива — **09:41**. Его можно изменить на экране полива. Даты посадки и затрат ограничены датой демонстрации.

Изменения записываются в приватный `files/orchard-state.json` через `AtomicFile`, фотографии — в `files/photos`. Повторный запуск сохраняет данные. Для возврата к исходным мокам очистите данные приложения в настройках Android или удалите приложение и установите заново. При удалении приложения локальные данные и фотографии удаляются.

Сервер, реальная ИИ-модель, Bluetooth-протокол принтера и оборудование полива не подключены. Моковый ИИ не анализирует содержание фото: он возвращает фиксированный пример. Синхронизации с React-дэшбордом нет. Камера, сканирование QR, хранение фото и системная печать используют Android API и работают независимо от мокового сервера.

## Где продолжать разработку

| Папка | Назначение |
|---|---|
| `data` | Сущности, начальные моки и локальное хранилище |
| `domain` | Плотность посадки, деньги, QR, пересечения интервалов |
| `state` | ViewModel и действия пользователя |
| `services` | Интерфейс диагностики, демоответ, фото, QR и печать |
| `ui/screens` | Экраны сада, осмотров, полива, затрат и служебных разделов |
| `ui/theme`, `ui/Components.kt` | Цвета, типографика и общие компоненты |

Для серверной диагностики замените `DemoDiagnosisService` реализацией `DiagnosisService` и подключите её в `OrchardViewModel`. Для общего API замените `MockRepository` сетевым репозиторием с локальным кешем. Для Bluetooth реализуйте адаптер протокола выбранного принтера вместо виртуальных устройств.

## Проверки

Сборка: `assembleDebug`. Проверки правил: `testDebugUnitTest`; исходники — `app/src/test/java/com/smartorchard/mobile/RulesTest.kt`. Покрыты плотность и округление посадки, неполный ряд, дубликаты культур, точные суммы, границы интервалов, даты, UUID QR, целостность зон, сериализация правок ИИ и граничные сценарии окупаемости.

В текущей Windows-среде запуск тестового процесса Gradle сталкивается с `Unable to establish loopback connection`; те же тесты можно скомпилировать и запустить напрямую через JUnitCore командой `.\verify-rules.ps1`. Результат проверки сборки и тестов записан в `VERIFICATION.md`. Эмулятор и физическое устройство отдельно потребуются для проверки камеры, печати, Bluetooth-адаптера и поведения интерфейса на разных экранах.
